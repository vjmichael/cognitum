## R1 production blockers and hard boundaries

- **Not an installed signed production service:** the SCM executable is unsigned and ephemeral; Cargo feature embeds **recoverable** test HMAC material and source-workspace paths instead of an independently installed publisher/provisioned OS credential broker. A matching MAC is only fixture-authentic, NEVER an original Lu Core per-turn PURE_COMPUTE grant. The real public Lu WorkspaceFrame gateway is still not wired to this SCM service.
- **No restricted/AppContainer SSM child:** the Python interpreter currently inherits the SCM LocalSystem token during this disposable fixture test. This is NOT acceptable for a production SSM numerical worker. Next stage must independently verify a restricted primary token/AppContainer identity and filesystem/cgroup-style I/O boundaries with service-owned Job. Do not authorize user-/model-controlled numerical work on the R1 fixture.
- **OS-staged input/TOCTOU:** source and input SHA values are pinned to CI build state, but staging resides inside a CI workspace, not an installer-protected ACL directory. A separate attacker-controlled file replacement between hash verification and worker open is not excluded by this fixture. Production must hold already-opened immutable handles and independently enforce installer-owned image/data ACLs, no symlinks/reparse ancestors, publisher/certificate pins and secure transport of the original typed request.
- **Not an independent signed stop or restart:** local fsync and write-once refusal are valid CI kernel custody observations, but records are self-written, unanchored HMAC-free and are not service-independent durable Ed25519 stop signatures with enrolled publisher/issuer, hardware/remote monotonic antirollback, process creation epoch and cold power-loss recovery. A signed test key or local service file is not sufficient.
- **Linux delegated recovery still blocked:** no real delegated cgroup2 subtree and installed separately supervised watchkeeper in this environment; the Linux job tests refusal to run a Windows SCM, not a positive delegated restart.
- **Real Core Health missing:** [Core #245](https://github.com/vjmichael/Lu-AI-GUI/issues/245) and [#248](https://github.com/vjmichael/Lu-AI-GUI/issues/248) still OPEN. Do not route via Lu Core's private SYSTEM-only SCM control pipe; Cognitum awaits accepted installer-signed public Health endpoint, original credential enrollment and Core-issued PURE_COMPUTE terminal receipt. No real Core Health response, output delivery or ACK occurred.
- **Physical acceptance:** a native GitHub-hosted VM is genuine Windows SCM/kernel execution but not the user's physical installed/approved production Windows host, not an independently signed release and not a permanent service upgrade/cancellation/reboot acceptance.
