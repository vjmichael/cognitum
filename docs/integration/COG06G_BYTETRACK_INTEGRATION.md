# COG-06G — Reviewed C15 ByteTrack association backend

**Status: planned, not implemented.** Preserve frozen COG-06A–F baseline `10dd3be219dd59a7e9a2f27fb6f958404e33ddb7` and current C15 implementation. Use the existing cooperative development branch, not a new branch. Owner request: incorporate ByteTrack where it is strong rather than replace all C15 capabilities.

## Evidence and intended boundary
On the accepted public-detector MOT17-02-FRCNN 299-frame validation sequence, matched official scores were C15 HOTA 30.435 / MOTA 25.111 / IDF1 32.961 versus ByteTrack 34.666 / 25.283 / 37.123 (percentage-point improvements +4.231 / +0.172 / +4.162). 4009 identical public detections; zero C15 capacity drops and 221 ByteTrack unassigned exclusions; official comparator preserved. This is one validation sequence, not universal superiority or proof of occlusion-specific gain. The existing tested comparator package is trackers==2.6.1; review its actual ByteTrack implementation, pin source/distribution and transitive licenses, CPU dependencies and installation on both platforms before selecting adapter implementation.

Use ByteTrack for temporal 2D association, particularly lower-confidence candidate association to existing tracks and short-term identity continuity, with high-confidence initialization and independently assessed recovery after occlusions. Keep C15's spatial geometry, calibrated depth, structural/volumetric reasoning, source ownership, and independent contract checks. Keep native C15's bounded association path for compatibility and comparison. Do not add a second canonical track authority or silent fallback/renumbering.

## Work and acceptance
1. Review native C15 track/update and lifecycle interfaces, tested comparator, original detector inputs and existing held-out assets; preserve current behavior. Implement CPU-only opt-in reviewed adapter, explicit backend identity/config version, source-linked frame/detection identity, fixed resource/capacity limits, normalized typed results and unassigned/invalid status.
2. Preserve track ID namespace, one-to-one assignment, lifecycle, scope/freshness/authority constraints and deterministic replay. Persist only validated versioned state or document unsupported restart; no silent state loss. Test malformed confidence/coordinates, duplicate frames, wrong scope, stale input, capacity, missing dependencies, discontinuities, cancellation/timeout and safe restart. No arbitrary execution, network, ground truth as inference input, or production activation.
3. Compare native C15, ByteTrack, and any explicitly designed cooperative policy on identical detections with pinned independent TrackEval. Keep original validation as regression; seek a distinct held-out sequence with lawful data access, not threshold tuning on evaluation ground truth. Measure HOTA, MOTA, IDF1, IDs, false matches, occlusion/recovery slices, unassigned, throughput, peak memory and CPU cost. Report raw counts and overhead. If held-out data is absent or gains not established, record limitations instead of claiming superiority or changing default.
4. Promote only reviewed bounded behavior supported by matched evidence, with source-bound CPU and security tests and one grouped acceptance. Preserve all earlier receipts and rejection gates. COG-07 follows; COG-10 and COG-11 remain separate.
