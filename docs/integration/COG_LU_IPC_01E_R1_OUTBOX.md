# COG-LU-IPC-01E-R1 — Cognitum-side durable R6/Lu outbox reconciliation, replay and uncertainty

**2026-11-21 source candidate — native acceptance pending.** Cognitum repository only. No Lu Core implementation changes.

## Source contract and strict trust boundary

- Continue source-pinned original Lu workspace v0 Git blob `4e01d921197fb1c58c99958479b1cede36e13c9a` and Cognitum SSM v1 `755562254afdbea686ee33b95567c505f2f85e49`. The original Lu `OperationReceipt.durable_receipt_sha256` is an evidence locator, **not** signed Core provenance.
- Reuse Cognitum's accepted R6 `HostSSMJournal` authenticated checkpoint, event journal and keyed pending-output checks; no new math engine, backend, server, tool registry, output publisher, execution grant, or broker.
- Extend accepted 01D `DurableLuOperationVerifier` to persist exactly one source-owned immutable canonical outbox-ID/body-digest inventory **inside the existing HMAC-chained, externally injected monotonic anchor log**. The original Lu terminal must be APPLIED with committed SSM typed result; its exact matched reconciliation must already be recorded. No outbox record is accepted after cancel intent/ack, host revocation, uncertainty hold or stale Core scope. Verify original event ID, SSM stream, observed revision/checkpoint hash and declared release count against original Lu domain receipt. Duplicate/replayed or inconsistent inventory is refused.
- The separate `lu_ipc_outbox.reconcile_unpublished_r6_outbox` requires the actual reviewed `HostSSMJournal` and `DurableLuOperationVerifier`, independently supplied Lu host origin/session/epoch and MEL Scope. It holds the existing MEL Admission lock while re-reading the authenticated R6 status and **complete** pending output set; refuses pagination beyond 256, other events, stale or advanced checkpoint, unverified pending rows, evidence unavailable, cross-session/turn/stream mismatch, revocation, cancellation and uncertain state. It records only SHA-256 inventory metadata in 01D. It **does not call R6 acknowledge**, deliver outputs, or assume exactly-once external publication.
- A one-way `uncertain_hold` appends to the protected 01D source-only audit and explicitly prevents any later output registration or automatic retry, even when the caller reconnects. Reconciliation after absent evidence remains UNKNOWN, not APPLIED; cancellation ACK is only signal-recorded, never proof of killed worker, rollback or successful delivery.
