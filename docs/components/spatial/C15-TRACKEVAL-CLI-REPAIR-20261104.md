# C15 MOT17 independent evaluation: TrackEval seqmap CLI compatibility repair

Date: 2026-11-04
Scope: **real public-detection research acceptance**, not an official MOTChallenge submission.

## Observed failure at PR #71 head 0e4823dc878c8b7c6ac11aaf7a3dccc5fd3259fb

The C15 real-data CI successfully downloaded MOT17-02-FRCNN public detections
and annotations, generated the C15 tracker predictions *before* ground-truth
evaluation, generated ByteTrack predictions from the same detections, and
staged the official TrackEval directory, including
`GT_FOLDER/seqmaps/MOT17-train.txt`. It reported 221 ByteTrack
unassigned (`-1`) prediction placeholders excluded from the official
TrackEval input, while preserving original artifact hashes.

The independent official evaluator then crashed before computing metrics:
`TypeError: stat: path should be string, bytes, os.PathLike or integer, not list`.
The pinned upstream `scripts/run_mot_challenge.py` parser registers
configuration values whose default is `None`, including `SEQMAP_FILE`,
with `nargs='+'`. Consequently `--SEQMAP_FILE <path>` is passed to
`MotChallenge2DBox` as a **list**, although `_get_seq_info` calls
`os.path.isfile(seqmap_file)` and expects a scalar filename. This was
a CLI contract mismatch, not evidence of a tracker/model failure.

## Repair

- Remove explicit `--SEQMAP_FILE` from `.github/workflows/c15-real-mot17.yml`.
  The pinned official scorer already locates the staged sequence map at
  `GT_FOLDER/seqmaps/MOT17-train.txt` by default.
- Apply the same change to the optional host-controlled
  `cognitum/spatial_official_trackeval.py` wrapper, retaining SHA-256
  verification of the required default seqmap before launching TrackEval.
- Extend the official-evaluation adapter regression to assert that the
  malformed CLI option is not passed and the default staged seqmap exists.

No GT/prediction roles, tracker outputs, confidence scores, identity mappings,
upstream evaluator source pin, or scores were changed. The optional
`pycocotools` BURST import warning was nonfatal and did not cause this
failure; no needless extra package installation was introduced.

## Acceptance still required

Run the actual official TrackEval `HOTA`, `CLEAR`/`MOTA`, and
`Identity`/`IDF1` metrics for both *frozen* C15 and ByteTrack
predictions on the same 299-frame MOT17 validation sequence; archive metrics
and staging hashes. The C15 practical core Windows/Linux native checks
had passed at the former head, but **the real-data gate must now pass on the
new exact SHA** before accepting the external evaluator integration.

This does not claim SOTA tracking performance or production authorization.
