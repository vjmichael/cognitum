## Mathematical contracts

- `proto/cognitum/mel/v1/exchange.proto` and checked-in compiler descriptor define content-addressed immutable Object/Body, typed scope, sample rows/columns, axis names/unit labels, optional declared source coordinate domain, binary vectors, explicit precision and assurance, parent hashes, source descriptor/kernel and approved checkpoint pin, threshold profile, transfer hash and cumulative loss flag. Transfer carries source IDs in order and exact destination request bytes/digest, operation/descriptor, destination checkpoint pin and scope. Strict canonical v1 wire profile, independent compiler comparison, domain-separated SHA-256 identity; no generic universal Protobuf canonicalization claim. Object limit 8192 bytes; transfer limit 65536 bytes; 32x8 samples, native 4096-bit HDC; each destination's existing lower limits still apply. All reviewed kernels, admission and descriptors remain untouched.
- Import native VFA point batches without changing binary64 values, axis names, units, signed zero or declared coordinate intervals. Import VFA scalar evaluations, KAN evaluations and HDC binding from a trusted host-owned completed Receipt, exact call/turn, request/result digests and checked response. VFA and KAN numerical results remain not certified. KAN binary32 values are exactly widened and explicitly marked as such; KAN currently has no authoritative units, so only explicitly host-declared dimensionless output/input mappings are accepted. No inferred units or normalization. HDC binding uses independent packed XOR witness. Q results remain in existing engine result type.
- Explicit threshold at >= supplied finite boundary in matching single unit (including equality), row-major bit encoding, profile includes original shape and labels. Always lossy even when a particular sample set happens to be binary. Exact bit lift to dimensionless 0/1 samples in explicitly selected bounded shape; no reconstruction of lost real values. Preserve source assurance and cumulative loss. Compare only equal HDC representation/threshold profiles; mixed origin, different threshold/layout/units refused. Matching positional profiles do not establish common semantic embedding, calibration, or probability. A host must choose meaningful comparisons.
- Prepare native VFA evaluate/gradient frame from aligned sample axes/unit labels and in-domain numeric points. Prepare native KAN evaluation frame from host-selected checkpoint and exactly representable binary32, dimensionless, in-domain rows; refuse silent rounding, out-of-domain or shape/unit mismatch. Prepare HDC query frame from same-scope matching encoding objects. Rebuild and check transfer from original objects and explicit target; no dispatch or authorization occurs in exchange. Host invokes existing Admission with separate operation grant, resource controls, live checkpoint pin and request ID. `from_transfer_result` rechecks transfer and original objects and imports completed numerical results with transfer identity and cumulative loss; standalone source imports are only for standalone host calls. A transfer digest is never a grant. Same-scope prevents accidental mixing; hashes and local records alone do not authenticate arbitrary external objects/receipts and cannot prove semantic correspondence. Trusted host must retain original sources and transfers, use reviewed derivations and prevent external fabricated lineage. No durable custody or automatic graph execution; no immediate worker interrupt or native Lu registration. General KAN/VFA function conversion, error bounds, multi-stage graph policy and actual LLM execution remain downstream.
