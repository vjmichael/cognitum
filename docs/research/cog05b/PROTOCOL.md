# COG-05B — Matched native exact-arithmetic feasibility protocol

## Scope and hypothesis

The accepted reference is Cognitum COG-04U at `826e4b9459e4b70413ef8f0813a4c41c2b609fae`. Candidate kernel only: scalar affine Sturm–Liouville weak-form assembly on the unit interval, clamped cubic spline basis, separated D/N/positive Robin endpoints; exact mass and stiffness matrices, rational LDL pivots, canonical receipt. No eigensolve, continuum certificate generation, training, worker integration or accelerator work in this experiment. The independent Python Fraction reconstruction is a secondary control for arithmetic/import isolation; accepted R/U source remains authoritative. No native implementation has been attempted.

Hypothesis: a compiled arbitrary-precision rational implementation (for example C++/GMP or Boost.Multiprecision, or a reviewed Rust equivalent) may lower assembly CPU time and memory while retaining exact receipt bytes. C++ is a candidate, not a language selection. FPGA suitability remains a separate future study.

## Frozen input/output and controls

- 24 historical fixtures: six R/U cases on 2, 4, 8, 16 cells. Four independently recorded U archives must have matching exact output bytes. Inputs contain only `problem` and `cuts`; expected digests are verification data, not kernel inputs. The local corpus is frozen by SHA-256. Full conformance uses the R contract: bounded exact rational coefficients, dyadic strictly ordered knots, endpoint rules, matrix/rational budget and PSD/SPD/null-space checks. Only trusted frozen fixtures are accepted by the independent pilot, not arbitrary inputs or an admission path.
- Required three arms: accepted dense R assembly, accepted support-aware U assembly, proposed native support-aware assembly. Fourth diagnostic arm: isolated Fraction reconstruction (both dense and support-aware) to separate dependencies/import costs. Match full canonical receipt including exact LDL witness, rational spelling, field order, bounds and refusal semantics. Native interface receives only inputs; independent runner compares complete outputs to reference. No digest lookup, approximate arithmetic, omitted checks, or reuse of outputs in timed workloads.
- Before implementation, freeze a separate correctness/held-out corpus with all nine endpoint pairings, nonuniform dyadic knots, extreme legal coefficients, exact null mode, invalid boundary/weight/coefficient/mesh/rational-budget cases, corrupted receipts and repeated deterministic runs. Generate with published fixed seed, verify against immutable R/U plus independent rational quadrature/LDL where applicable; hold out from optimization. No post hoc exclusions or correctness tolerance for exact results. Preserve expected refusals and log unexpected failures.

## Measurement protocol

Use same physical host and OS image within a comparison, fixed CPU affinity, explicit frequency/power policy, one thread, recorded CPU and compiler/toolchain packages, release flags, library versions and hashes. Capture complete source commit, dependency lock and executable digests for all arms. Build without downloads from pinned dependencies; capture clean-build and offline restore evidence. Benchmark 9 independent paired fresh-process repetitions with balanced randomized order (fixed seed); also 3 unmeasured warm-up passes plus 9 paired warm-process repetitions for steady-state compute. Warm-up excluded; report cold launch/import/setup separately. Use the same input corpus, exact canonical serialization and full assembly+LDL scope. Record per-case and total CPU time, elapsed time, current resident bytes before and after, lifetime peak RSS/working set with platform method, sampled incremental resident peak if available, output size, and optional energy only if a calibrated counter exists. Record environmental noise and all samples. Use per-pair ratios, median, spread and a seeded paired bootstrap 95% interval; 9 pairs is an initial feasibility sample, not universal significance. Avoid cross-OS RSS comparisons or multiplying unrelated speedups.

Proposed research acceptance: all positive and negative correctness controls pass exactly on each tested host, independent verification of mathematical witnesses passes; on the primary host median CPU speedup vs accepted U >= 1.5x and lower 95% paired bootstrap bound > 1.0, with no >10% median warm CPU regression in any preregistered workload class. A memory improvement requires separately evidenced >=20% reduction on a comparable resident or peak metric; otherwise report no demonstrated memory gain. These are prospective feasibility thresholds, not established results or mandatory production criteria. Report failed hypotheses; no silent retuning. Native CPU and Windows replication, full portable environment lock, hardware counters and independent peer theorem review remain open. No kernel promotion, changed contracts, or language migration without owner approval.

## Local isolated reference

On Linux, use `/usr/bin/python3 -I -S reference.py run Cognitum_COG-05A_evidence.zip NEW_OUTPUT_DIR` (or the included `u-evidence.zip`, containing the four original U archive payloads at their original paths). No pip dependencies, network or model needed. Python binary and stdlib source fingerprint are recorded; this is a host fingerprint, not a full reproducible OS image. The pilot uses three alternating *fresh-process* samples per arm on one hosted CPU and verifies all 24 outputs each time. It is not a native-language benchmark or execution of accepted R/U modules. Local `host-lock.txt` records observed OS/packages/library digests; `environment.json`, `corpus.json`, `results.json`, and `rejection.log` retain provenance and raw samples. The process CPU timing covers reconstruction, exact LDL and receipt serialization, excludes import, corpus parsing and output digest checks. Launch elapsed includes those operations. Peak RSS can inherit pre-exec/fork high-water and is not a pure allocation measurement; instantaneous RSS before/after is not a sampled peak.
