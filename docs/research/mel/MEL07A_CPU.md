# MEL-07A — bounded CPU mathematical backend qualification

Status: source implementation candidate; native acceptance pending. Scope: existing VFA evaluate/gradient, binary HDC binding/query and pinned scalar KAN evaluate. Keep MEL-06B-B deferred until Lu is ready. No Lu changes. CPU-first and research default-off are unchanged.

## Method

`cognitum.mel.cpu_routing.select_cpu` returns an inert selection of the existing nominated, enabled, exact reviewed CPU factory. An unavailable/disabled/stale entry or explicit non-CPU preference fails closed. Selection is not authorization or dispatch. Existing Admission remains the independent grant and actual worker boundary. No implicit accelerator fallback, duplicate registry, or alternate runtime.

`python -m tools.mel07a_cpu --out mel07a-evidence/qualification.json --repeats 3` executes 30 admitted calls, 10 representative deterministic cases, and 210 direct warmed samples of the identical plugin and payload. Each actual spawned worker result must be byte-identical to direct plugin output; independent scalar Gaussian/gradient and simple RBF KAN reference and exact binary XOR/Hamming oracles check every component. Existing MEL certificate/receipt rechecks remain mandatory. HDC exact, VFA scalar absolute error <=1e-10, KAN <=1e-5, with the pre-existing independent certificate tolerance unchanged. This scalar cross-check is not itself a certified enclosure. Timing scopes separate preparation, direct plugin, admitted worker and verification. No thresholds that force a speedup or ignore failing numerical results. Work counts are logical accounting proxies, not actual FLOPs.

CPU thread environment requested at one for common BLAS/OpenMP runtimes before NumPy import. Record platform and dependency versions, source SHA, request/result hashes, actual timings, own/reaped-child CPU time deltas where available and actual process-lifetime RSS/working-set high-water. Linux largest reaped child high-water is not summed simultaneous tree RSS; Windows child CPU/RSS unavailable. No memory claim beyond measured scope, no power measurement, no physical hardware comparison. Direct warmed control differs from spawned worker in initialization/custody/verification cost; ratio is overhead characterization only, not backend superiority.

Routing negative controls include strict unsupported backend requests, research default-off, stale descriptor, missing/disabled and substituted factory, resource admission refusal, replay and revoked grants. Existing cancellation/recovery tests remain intact; active cancellation performance is not measured by this benchmark. Run with existing four native Python cells; artifacts uploaded even on failure. Current source not accepted until all cells and existing integration batch conclude. Expand to polynomial/tensor/cooperative and matched maintained-library backends separately. No GPU/FPGA/ARM promotion, no installed Lu or general efficacy claim.

Prepublication inspection bounded the larger HDC case to 768 bits with eight candidates to fit the existing model envelope. Direct seven-sample, admitted-worker and verification CPU deltas are recorded separately. Summaries retain raw samples and per-case medians. No local complete source checkout was available; native hosted execution is the qualification gate, not prepublication inspection.
