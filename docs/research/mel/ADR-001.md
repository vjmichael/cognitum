# ADR-001 — Adopt the unified Cognitum Mathematical Execution Layer

Status: owner-authorized MEL-01 architecture baseline; implementation and hosted acceptance pending by phase. Source baseline: [934fcda2](https://github.com/vjmichael/cognitum/commit/934fcda26ac54856675db50fd9e7fa4986424e9a), native [44443339840](https://github.com/vjmichael/cognitum/actions/runs/44443339840), all 18 jobs passed, all four HDC cells logged 42+27+48 VFA tests with zero skips/errors/failures, 96+38+93 benchmark rows. Archive ZIP bytes have not been independently rehashed for this audit. This decision adopts the direction of [ARCHITECTURE.md](ARCHITECTURE.md) while preserving it byte-for-byte as the original design.

## Decision and scope
Extend one Cognitum runtime and the existing Lu-owned model tool/host boundary. Do not create a second plugin registry, worker manager, orchestrator, scheduler, agent loop, authorization service, or canonical memory database. Mathematical engines retain independent native representations and overlapping functionality; shared conventional mathematics is a complement, not evidence of native HDC/KAN implementation. Keep established specialist routes working, CPU-first. GPU, FPGA and neural/latent model integration remain separately qualified research.

The logical path is Lu user/LLM -> reviewed tool schema and host grant -> typed MEL operation and object -> existing runtime/registry/policy/worker -> engine -> independent verification / cooperative graph -> typed result/receipt -> Lu. Canonical artifacts/revisions/persistence remain under host ANSF ownership. Actual model selection, typed calls, execution, result interpretation, cancellation and recovery require installed host acceptance. No model weight change required for the first slice.

## Common mathematical object obligations for MEL-02
Versioned immutable object identity, content digest, kind, specific representation and schema version, shape/arity, domain/codomain, units, coordinate/basis/codebook identities as applicable, precision and arithmetic format, assumptions, limitations, assurance and error descriptor, source/parent lineage and producer/checkpoint identity, bounded bytes or opaque host-owned handles. No lossless conversion assumed; each representation-specific codec/bridge declares compatibility, domain and approximation semantics. Explicit unknown, unsupported, refused, stale and cancelled outcomes. No host authority in metadata or a mathematical result. First implementation should support bounded Gaussian VFA objects, finite coordinate batches and scalar/gradient results; expand to HDC role vectors and approved KAN handles without forcing a universal array representation.

## Phase gates
- MEL-01: exact-source architecture/metadata reconciliation, 164/85 accounting, independent source preservation, 12 local metadata tests; hosted consolidated gate pending.
- MEL-02: typed mathematical object codec, domain/shape/representation/units, bounded immutable handles and lifecycle; test VFA evaluation and gradient round trips with independent oracles, no model exposure yet.
- MEL-03: reviewed model-facing descriptors, schema binding and explicit host admission including denied/unavailable/stale/wrong scope, no registration from model text; approved KAN inference and HDC binding/query as separate slices.
- MEL-04: admitted cooperative graph bridges and conversion, independently checked results, cancellation/revocation and publication semantics. No cross-engine capability claim until measured.
- MEL-05: verification/error semantics, align VFA-04 interval and numerical qualification; separate mathematical exactness, certified enclosure, conditional statistics, empirical validation and unqualified approximation.
- MEL-06: genuine local GGUF tool discovery, selection, invocation through native Lu host, results and correct interpretation, negative controls, matched conventional and unassisted model comparisons. Never substitute a fabricated tool response.
- MEL-07: qualified CPU/GPU/FPGA/optional distributed backend routing, timing/energy only on actual measured devices; cancellation/recovery and fidelity.

Prioritize a minimal live model-to-VFA path early; do not wait for every mathematical category, nor block independent research on speculative deep model integration. After MEL-02, coordinate VFA-04 with MEL-05 and stage MEL-03/04/06; continue further depth research on the same contracts. Host changes need separate approval. No automatic merge, promotion or release.
