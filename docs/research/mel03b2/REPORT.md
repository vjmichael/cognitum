## Interface and authority

`cognitum.mel.admission.Admission` wraps the existing trusted Runtime, one instance per host session. Only a trusted host issues a grant; random 32-byte tokens never appear in model schemas or admitted Protobuf frames. `Scope` binds session, workspace, subject and turn. `Route` is a reviewed compute-only classification with exact existing native descriptor digest, operation version and input/output type URLs. Discovery rechecks the exact live nominated entry and only returns that grant's tool schema. It does not register any Lu tool. The only current routes are VFA evaluation and gradient. No arbitrary effects or plugin authority are introduced. The original Runtime research entry point remains available to trusted code; the new interface is not a sandbox against malicious Python code or the sole deployment enforcement point until host integration.

`execute` accepts raw native VfaRequest bytes, validates canonical protobuf, exact route, host request ID, turn correlation, object compatibility and budgets, and uses the existing Runtime worker. It rechecks the live installed registry entry under its lock and revalidates the returned native VfaResult, including parent lineage, descriptor, request/correlation IDs, representation and numerical assurance. Immutable scoped receipts bind the exact request and validated successful result bytes by SHA-256; no failed, cancelled, revoked, expired, malformed or oversized result is published. A hash is not an attestation or mathematical proof. Existing numerical/not-certified limitations remain.

## Limits and lifecycle

Host-selected bounded dimensions, terms, sample points, request and result byte sizes, timeout, call count and cumulative work proxy `(terms+1)*dimensions*points`. Default grant: 8 dimensions, 32 terms, 16 points, one call, 3 seconds, work 4224; maximum 60 seconds grant TTL and 10 seconds requested timeout. Absolute engine caps inherited; 64 grant slots, 256 scoped replay tombstones, 4 reserved in-flight calls per Admission. Capacity exhaustion fails closed; no silent replay eviction, no automatic retry/refund. Work units are a conservative input-shape proxy, not measured CPU, RAM or energy; output budget is enforced before publication, not as a worker allocation quota. Validation is bounded by native frame caps; a trusted host must bound its own incoming request queue. Each admitted request consumes budget even if later cancelled, refused or timed out. Same request ID across grants in the same scope cannot replay; distinct turns may independently use the same ID.

Revocation, active cancellation and session close are linearized with result publication. Queue cancellation is observed before dispatch; once dispatch is committed, existing trusted inert worker can complete or reach Runtime timeout, with results discarded on cancellation, revocation or expiration. The exact installed registry entry is pinned by the existing registry lock through dispatch and result verification; this serializes calls sharing that registry and means registry mutations may wait for worker cleanup. Absolute host deadline controls queueing and remaining worker timeout, and late results are suppressed; worker teardown and scheduling can exceed that deadline. Cancellation is not immediate preemptive process termination. Existing Runtime timeout containment is not protected OS custody. Grants and tombstones are bounded in-memory session state, not durable cross-process grants or receipts. Retire the instance on shutdown; protected Lu host grant issuance, OS worker termination, durable ownership/journaling, true model registration and installed model-to-tool evidence remain explicit integration gates. No direct authenticated Lu connection or C++/Rust round-trip qualified.
