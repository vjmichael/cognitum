## R5 prospective irrevocable experimental plan — no test history yet

Original [PREREG](ORCH01E_BENCH02_R5_PREREG.json) fixes:

- **New independent stations** KBOS, KMSP and KPHX, exactly in this order, no replacements; first complete window starts at the first UTC midnight strictly after *both* independent witness lanes have authenticated start captures, and no earlier than November 23, 2026 UTC.
- **28 full UTC days**, 672 hourly bins: **336 train, 168 calibration, 168 test**; original 1/3/6-hour forecast horizon targets, frozen 0/1/3/6/24-hour history lags; no train/cal/test label crossing. Forecast is issued at bucket end plus 20 minutes and scored only on later observed target values. Each feature must have two original source witnesses archived before issuance.
- **Every 10-minute source sampling**, two independently run collectors A and B; each original restricted NOAA HTTPS JSON response is archived as its exact bytes, SHA256, original source timestamps, explicit sequence ID and predecessor hash, including negative/empty/error/gap outcomes as separate measured missingness rather than retrospective imputation. Requests remain strictly below the NOAA API [published access limits](https://aviationweather.gov/data/api/), with fixed user-agent and bounded payload. For each record, its **independently retrieved GitHub artifact creation timestamp** must precede the forecast issue, both witness runs must be distinct, their original ZIP bytes/SHA and chain order independently checked. No single receiver wall clock or AWC-reported `receiptTime` is sufficient.
- **Critical epistemic boundary:** independently timestamped first *seen by these two collectors* is testable. Without a publisher-signed issuance log, nobody can claim the instant NOAA first made the observation public worldwide. The protocol **never** upgrades two-witness first-seen evidence into that stronger unproven statement. GitHub artifacts establish third-party archived custody no later than issue time, not NOAA publisher-side cryptographic authorship.
- **Science frozen**: previous direct ridge and original deterministic research SSM/HDC/KAN methods, persistence/mean/AR24 classical controls and actual original default/research Orc selector with unchanged 1e-10 K portable near-tie refusal. Training only train; model selection only calibration; test labels independently scored only following frozen per-origin decisions. No tuning the old 265 R4 heldout labels.
- **Honest denominator**: every original site/horizon and refusal reported. Complete nine-cell equal-weight macro requires all nine cases; otherwise report signed case-level metrics, missingness and no full macro. Dependence-aware intervals use 6-hour disjoint blocks and refuse tiny datasets. First prospective superiority claims would require stronger genuinely independent replication and multiplicity controls.

## Provenance/integrity implementation and native qualification scope

`tools/orcbench02/prospective_r5.py` implements source-locked AWC response capture, exact unmodified source-byte encoding, typed row and report-hour verification, hash-chained per-lane records, a production GitHub REST metadata **and ZIP download** verifier, independently anchored pre-issue admission and a separate post-issue future-label reveal. The production ledger path accepts **artifact IDs, not arbitrary self-reported metadata objects**. `synthetic_fixture=True` in the explicit test harness does **not** establish real NOAA availability; tests independently assert that passing local JSON cannot silently be treated as an actual production witness. A shared lane/run, wrong station, source hash tamper, backdated calendar time, 429/non-JSON response, broken or missing sequence, over-frequent polls, 25-minute-plus gaps, source revisions and future leakage must be refused.

`.github/workflows/orcbench02-r5-manual-capture.yml` is intentionally **manual-only**: the operator must separately authorize each source poll and specify its lane and source hash predecessor. No scheduled 28-day collection or background CI is created here. A future durable collection service with authenticated external anchors, bounded artifacts and operating cost needs separate operator authorization and qualification. The R5 methodology is valid only if its full 672-hour prospective collection is actually populated and independently verified before fitting.

`tools/orcbench02/audit_r5.py` independently downloads/replays all nine historic original ZIPs (input supplied by an authorized GitHub-connected host), verifies their original JUnit and CI source SHA receipts, checks all R4 vs native source pair clocks/labels/direct-ridge identities, then replays the actual original KAN/HDC/SSM model metrics and all abstentions. The source-only Windows/Linux Python 3.11/3.13 native CI workflow qualifies the frozen R5 protocol, source admission refusals and original historical negatives; a separate independent source replay job uses real archived original ZIPs, not manually copied summary values. This is **not new model forecasting acceptance** and grants no production authorization.
