## Original source and rights
The [NOAA/NWS Aviation Weather Center Data API](https://aviationweather.gov/data/api/) exposes aviation METAR records in JSON, with original raw report, reported Unix observation seconds, AWC-reported receipt time and temperature. Its public documentation limits historical records to the previous 30 days, generally 400 results per query, and requests to 100/minute. Qualify one predetermined station KMCI and 3-hour window solely for genuine source acquisition, not for model selection. Acquire at most one 2 MB HTTPS request with a custom user agent and system trust store; reject HTTP redirects, non-200, non-JSON and wrong station/fields. The archived JSON is the original provider response, not a generated fixture. The publisher and public data origin do not constitute an independent signed original-instrument feed.

## Original byte custody
Python implementation: tools/orcbench02/acquisition.py.

Each response retains source URL, original raw bytes, SHA-256 and byte length, host-clock start/end, server Date header, HTTPS trust path description, GitHub run context, exact report row indexes, literal original report, original row SHA, UTC observation/receipt clocks, and missing temperature (not imputed). Repeated timestamps and corrected versions are preserved in provider order rather than refused, scored selectively, or silently deduplicated. The first-seen boundary for a previously unseen version is the completion timestamp of its first acquisition; re-observation of the same byte-equivalent record does not change it.

Receipts and unmodified snapshot bytes have a canonical SHA-256 hash chain, sequence numbers, creation-only open, POSIX user-only file/directory modes and fsync, with complete replay verification before each append. A half-written/orphaned entry, missing source, rewritten original, forged first-seen value or broken sequence refuses. Windows tests qualify the data and record contracts, not Windows ACL/WORM custody.

## Exact acceptance distinction
A GitHub-hosted native runner's untrusted wall clock, HTTPS system CA, response Date and SHA-chained local files can **corroborate** that a record was retrieved during a documented CI run but do NOT independently prove the first time it was publicly available. A single actor controlling both source journal and receipt can replace all entries, or roll the entire head back: externally anchored signing, protected key custody, independent timestamping and installed durable audit are NOT part of R2. AWC receiptTime is not an independently signed public-availability timestamp. Predictions for an earlier historical origin are not permitted to use the newly acquired record. The research-only as-of view refuses any observation/version with observed, AWC-receipt or first-capture times after an origin. Production authorization stays false.
