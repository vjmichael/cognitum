# MEL-06B-A — Cognitum-side Lu adapter (2026-11-19)

Scope revised by owner: create the adapter now; **defer all Lu integration until Lu is ready**. No Lu repository changes, installed-model acceptance, CE installation or production enablement. This supersedes the implementation scheduling in INSTALLED_PREFLIGHT.md, not its evidence.

The Python adapter `cognitum/mel/lu_adapter.py` provides an inert review proposal for five reviewed operations (VFA evaluate/gradient, HDC bind/query, pinned KAN evaluate). It returns existing public tool schemas, native Protobuf type URLs, descriptor/codec identities and the required compute-only effect; metadata is not a new IPC protocol. No automatic registration, worker launch, authorization, or model advertising. A separately selected trusted registry, exact route and codec identities, independent typed intent, approved checkpoint when required, and host request ID are input to `prepare`; model data is only the closed JSON request. Existing codecs bind both independently expected and model-generated data, requiring exact Protobuf equality. No input rewriting. The immutable candidate carries no grant.

The host must take responsibility for the next step: independently validate/authorize the candidate's exact bytes, dispatch through its existing protected worker and authenticate the retained receipt. `verify_host_retained_receipt` checks the scope, identity, request/result hashes and mathematical verification using the existing MEL independent replay functions. It produces a detached result candidate, not permission to publish. Hashes do not authenticate transport or prove receipt origin. Host must enforce cancellation/revocation, freshness, replay, recovery and publication atomically at its own boundary. Adapter performs no independent host lifecycle, canonical memory, registry creation or permission decisions. Reference-only status is explicit in every proposal and candidate. Polynomial/tensor/cooperative graph routes are not yet exposed through this initial adapter; their existing MEL research source remains untouched.

Tests exercise five actual reference workers and refusal controls for stale codecs/descriptors, changed typed inputs, signed-zero, component and checkpoint mismatch, wrong scope/request identity, noncompleted receipts with payload, and a hash-consistent erroneous HDC result. These tests use the existing reference Runtime/Admission; not installed Lu and not proof of security custody. New tests are wired through regular unittest discovery; source candidate awaiting native acceptance. No new dependencies. Existing Lu and Cognitum research contracts unchanged.
